## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Fixtures come first (CLAUDE.md): before any A2UI parsing or policy code, PaddockCore needs real A2UI v1.0 messages in both directions. The official corpus (a2ui-project/a2ui at tag v0.12.0+swift: specification/v1_0 examples, catalogs/basic/v1/examples, conformance/test_data) is the real source; it is Apache-2.0, so the copy keeps a license and provenance note.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Fixtures/a2ui holds agent-to-renderer v1.0 messages (createSurface, updateComponents, updateDataModel, deleteSurface, callRendererFunction) covering every basic-catalog component and function, including Image, Video and AudioPlayer with https, relative and data: URLs
- [x] #2 Fixtures/a2ui holds renderer-to-agent v1.0 messages (action, error, function call and response) as the Swift library emits them

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Pin A2UI v0.12.0+swift. 2. Copy the upstream v1.0 basic examples, the contact-form stream, the spec's valid function-call cases, the basic catalog and the license. 3. Write two Paddock fixtures for what upstream lacks (media sources; numeric, not, pluralize) and check them with A2UI's Swift validator. 4. Capture renderer-to-agent messages from A2UI's Swift core with a reproducible task (capture:a2ui; OpenCombine on Linux). 5. README with provenance; test resource and fixture tests.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A2UI's Swift core runs on Linux with OpenCombine for capture only (tools/tasks/lib/a2ui-capture-patch.py); pluralize crashes there (Bundle.module.localizedString with a stringsdict), so functions, product-card and recipe-card yield no actions on Linux. Seen in the capture: failed button @checks send VALIDATION_FAILED with the button id as path instead of an action (renderer/checks.jsonl); an unknown version is reported with version v0.9; function-call actions (openUrl) send nothing; a Column naming a missing child reports nothing. Renderer function-call messages (callAgentFunction, rendererFunctionResponse) are the spec's valid cases, not library output: the library's own come with PAD-146.3 on the Mac.
<!-- SECTION:NOTES:END -->

## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Paddock must check what crosses between the sandbox and an A2UI tab without linking A2UI (it does not build on Linux). Deep validation stays in A2UI's PayloadValidator on the Mac; PaddockCore holds only Paddock's own limits and the media rule that the Mac never fetches an agent-chosen URL.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A2UI JSONL from the sandbox is split into messages with caps per line, per tab and in total; an oversized or non-JSON line is refused with a reason, without dropping the valid ones
- [x] #2 Only v1.0 messages naming the basic catalog id are accepted; others are refused with a reason the agent sees
- [x] #3 Renderer-to-agent messages are size-checked before they reach the sandbox
- [x] #4 A media reference resolves to exactly one of: fetch in the sandbox (http/https), read a sandbox file (relative path, no escape from the tab folder), decode on the Mac (data:, size-capped); any other scheme is refused
- [x] #5 sbx exec arguments for sending, waiting and fetching are built in one place; JSON never carries secrets
- [x] #6 Every rule is covered by fixture-based tests that pass under mise run test on Linux
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. A2UIPolicy (Agents/A2UIPolicy.swift): v1.0 and the basic catalog id; per-message (line) and per-tab byte caps. 2. A2UIInbox: a tab's message log is JSONL the sandbox helper appends to; Paddock reads it from an offset and takes whole lines only. Each line is checked (JSON object, version 1.0, exactly one known kind, basic catalog in createSurface and callRendererFunction); valid lines pass on as their own bytes, unchanged; each refused one becomes a Paddock event for paddock wait ({"paddock":"refused","line":N,"reason":...}), and the rest continue. 3. Outbound: a renderer message (known kind, one line, size cap) or, when too large or malformed, a Paddock event saying so; sent on stdin (sbx exec -i), never argv, since an obscured TextField's value is a secret. 4. A2UIMedia: url -> sandboxFetch(http/https) | sandboxFile(relative path, NativeShowPolicy.isRelativePath) | inline(data: image/video/audio, base64 or percent) | refused(reason); fetched output '<mime>\n<base64>' parsed with a size cap and a MIME family per component. 5. A2UICommands: every sbx exec for A2UI tabs (read messages from an offset, deliver a line on stdin, fetch, read a file). 6. Tests from Fixtures/a2ui.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Outbound lines go on stdin (sbx exec -i, as SandboxWatchers already does), never argv: an obscured TextField's value is a secret, and argv shows up in SbxError text. With stdin the outbound cap is 256 KB. A tab's media is capped at 40 MB, what fits FoundationProcessRunner's 64 MB output cap as base64 (the plan said ~200 MB). Paddock builds no wait command: the agent runs paddock wait in the sandbox; Paddock's side is reading the log (--messages ID OFFSET), delivering (--operator ID a2ui, stdin), fetching (--fetch ID URL, prints Content-Type, newline, base64) and reading files (--read). The sandbox helper implements those in PAD-146.4. Outbound messages are not checked for version 1.0: A2UI reports an unknown version with version v0.9 (Fixtures/a2ui/renderer/errors.jsonl).
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
PaddockCore now has A2UI tabs' own rules, with no A2UI dependency, tested on Linux. A2UIPolicy: v1.0 and the basic catalog only; what a tab sends back becomes one line for paddock wait (unchanged, or an A2UIEvent when it is over 256 KB or not a renderer message). A2UIInbox reads a tab's JSONL message log from an offset, takes whole lines only, and checks each on its own (JSON object, version 1.0, one known kind, basic catalog in createSurface and callRendererFunction, 512 KB per line, 8 MB per tab); valid lines pass through as the agent's bytes and each refused one becomes {"paddock":"refused","line":N,"reason":...} without stopping the rest. A2UICommands builds every sbx exec for a tab (read the log, deliver on stdin so typed secrets never reach argv, fetch in the sandbox, read a file). A2UIMedia resolves Image/Video/AudioPlayer URLs to exactly one of sandbox fetch (http/https), sandbox file (relative, no escape), or inline data: of the component's MIME family, and refuses every other scheme; fetched bytes must be of the component's family and at most 40 MB. A2UIPolicyTests (15 tests) run every agent and renderer fixture through it plus the edge cases; mise run test (663) and mise run lint pass on Linux.
<!-- SECTION:FINAL_SUMMARY:END -->

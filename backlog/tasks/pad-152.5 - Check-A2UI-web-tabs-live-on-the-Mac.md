## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Found in the first live use: in a sandbox created with the base kit from before PAD-152.4 (OpenUI reference, while paddock already pointed at a2ui.md), agents guessed the catalogId and every createSurface was refused. Recreating the sandbox installs the A2UI reference. The refusal now quotes the catalog the agent named and points at /usr/local/share/paddock/a2ui.md, so an agent without the reference can correct itself.

Live: the tab was blank. The system log (hang capture 20261125-092351) showed the page's main request sent to WebKit's network process and failing with -1002: A2UIWebTab set its scheme handler on the configuration after making the WKWebView, which copies its configuration at init. Fixed by setting both handlers (weak proxies) before; a failed load now shows the fail-closed page and says why in the Log, about:blank (that page) is allowed, and a stopped web content process loads the page again.
